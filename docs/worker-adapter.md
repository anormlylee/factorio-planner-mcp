# Worker runtime adapter

The application keeps one catalog, recipe adjustment, LP construction and MCP tool registration implementation. Package imports `#catalog-data` and `#solver` resolve to Node providers by default; Wrangler aliases resolve them to Worker providers.

Node reads the snapshots from disk, verifies data hashes and uses GLPK.js's original Node entry point. Workers import bundled JSON; the build verifies hashes before bundling. Both use the same pinned GLPK.js 5.0.0 WebAssembly binary.

GLPK.js 5.0.0's published Node wrapper does not expose Emscripten options and assumes a host filesystem. `scripts/prepare-worker.js` applies asserted, reproducible transformations to the installed distribution:

1. Forward options from the exported factory to the underlying GLPK factory.
2. Disable Node environment detection for this generated Worker-only copy.
3. Keep `/out` in Emscripten's memory filesystem rather than mounting the host filesystem.
4. Await the custom WASM instantiation Promise before running Emscripten's runtime initializer.

`solver-worker.js` supplies the precompiled module Wrangler creates from the `.wasm` import. The callback is deferred to preserve Emscripten initialization order. No solver mathematics or LP calculation is changed. GLPK's JS/WASM are not fetched from the network at runtime. Generated files are ignored in Git and regenerated by the Wrangler custom build; unchanged files are not rewritten, avoiding dev-watch rebuild loops.

The source package and build scripts are available at https://github.com/jvail/glpk.js (version 5.0.0), with GNU GLPK sources available at https://www.gnu.org/software/glpk/. The npm dependency contains the GLPK integration C source, Makefile, and JS wrappers. Follow the upstream build instructions/toolchain to rebuild its WASM. This repository's lockfile pins the package and its integrity; the adapter checks the package version and every transformation anchor before writing generated artifacts.

Workers use the SDK's WebStandardStreamableHTTPServerTransport, with one stateless server/transport per POST and JSON responses. Resource cleanup is scheduled after handling each request. The platform rate-limit binding applies to the connecting client IP. It is local to a Cloudflare location, not a global account quota. No client-controlled request host is used to fetch external data.

`npm run test:worker` exercises actual workerd HTTP and WASM execution (initialize, discovery, Chinese search, recipe lookup, quantum coolant loop, location conflicts, barrel materials, bad Origin and oversized body). Run `npm run dev:worker` first. Normal `npm test` continues to cover Node/Docker/stdio behavior.
